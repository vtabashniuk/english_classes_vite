# CRM — підсумковий аудит регресійного покриття, 1.5.2

Дата: 2026-10-12. Підстава: архів коду після 1.5.1 плюс ZIP-файли регресійних наборів 1.5.2a–g, включно з виправленими версіями e/f/g. Останню Git-історію гілки 1.5.2 безпосередньо не перевіряли: підтвердження комітів і SQL PASS надано власником CRM.

## Підтверджено

- JavaScript: 81/81 PASS під час повторного запуску на реконструйованій копії коду.
- SQL pgTAP: 264/264 PASS у локальному Supabase за звітом власника.
- 66 міграцій у перевіреному архіві; наявний окремий GitHub Actions `Quality checks` для JS, lint, архітектури та Vite build.
- Основне покриття: ізоляція користувачів, ключові RLS, створення уроків/конфлікти, перенесення, скасування, автоматичні результати, регулярні серії, тарифи, паузи, валютні платежі, ЄП/ВЗ/ЄСВ, ідемпотентність платежів.

Число тестів **не** є відсотком покриття коду та не доводить безпомилковість усіх процесів.

## Прогалини за пріоритетом

| Пріоритет | Сценарій | Зафіксована прогалина | Наступний контроль |
|---|---|---|---|
| P1 | Фінансове блокування учня | SQL-тести не викликають `temporary_unlock_student_financial_access` та `reconcile_student_financial_access` | Борг → блокування → тимчасове розблокування → фінансова операція → повторна оцінка |
| P1 | Materials & Assignments | Немає SQL-сценаріїв RPC `grant_collection_materials_to_student`, `create_assignment`, `update_assignment`; перевірено RLS і revoke/restore | Власні/чужі матеріали, bulk grant, завдання не обходить відкликання доступу |
| P1 | Нагадування | Немає SQL-викликів `dispatch_due_assignment_reminders` і тесту `assignment_reminder_events` | Одне нагадування на дедлайн, повторні виклики без дублів, новий дедлайн після перенесення |
| P1 | CI | GitHub Actions раніше не виконував SQL pgTAP | Додати ізольований PostgreSQL через Supabase CLI у наявний required job |
| P2 | Запити на перенесення | Немає повного інтеграційного тесту запиту учня і рішення викладача | Додати, якщо змінюється модуль або виявлено регресію |
| P2 | Прочитання/ретенція повідомлень | Немає SQL-тестів `mark_notification_read`, `mark_all_notifications_read`, запланованого очищення | Перевірити у наступному контрольному наборі |
| P2 | Часові пояси | Дедлайн уроку враховує `teacher_settings.schedule_timezone`, а `assignment_reminder_eligible_at`, due-day dispatcher та клієнтський `assignmentStatus.js` використовують `Europe/Kyiv` | Окремий негативний тест на інший часовий пояс; виправлення лише за підтвердженням сценарію |

### Межі аудиту

Проведено статичне зіставлення тестів з актуальними міграціями, функціями та джерелом React. Не виконувались інтеграційні тести з живими Google/Apple/Microsoft OAuth, NBU API, SMTP, платіжними провайдерами чи Production. Їх не можна вважати пройденими через pgTAP.

## Узгоджений шлях завершення 1.5.2

1. **1.5.2h — SQL у GitHub CI.** Залишити назву `Quality checks`, щоб чинний Ruleset продовжив вимагати її успішного проходження. Перевірити перший запуск у GitHub, включно зі стартом ізольованої БД на чистому runner.
2. **1.5.2i — цільові SQL-тести критичних прогалин.** Першочергово фінансовий доступ, bulk grant і дедуплікація нагадувань. Використовувати лише локальний Supabase, синтетичні записи, транзакційні відкати. Уникати змін бізнес-логіки заради тестів.
3. Після успішного 1.5.2i завершити 1.5.2 та перейти до 1.5.3 (документація, оцінка оптимізації збірки). P2-питання залишити у контрольованому backlog.

Production БД, Vercel та вже застосовані міграції не змінювати в рамках цього аудиту.
