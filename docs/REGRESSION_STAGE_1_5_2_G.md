# CRM — регресійні тести 1.5.2g: валюта, податки, ЄСВ

## Призначення

Тільки локальний pgTAP-тест `07_fx_tax_esv_regression.sql`. Не додає міграцій і не змінює код CRM. Працює на синтетичних ідентичностях `crm-tests.invalid`, без Auth email, реальних валютних курсів або викликів NBU API. Кожен тестовий файл запускається у власній транзакції `BEGIN / ROLLBACK`.

## Перевірені бізнес-правила (52 assertions)

- Створення податкового профілю ФОП/PE групи 3 через RPC і розділення PE / personal рахунків.
- Гривневий дохід PE: 5% ЄП + 1% військового збору від фактичного платежу, окремий знімок податку.
- Однакові гривневі платежі двох студентів: місячний ЄСВ за ставкою 22% від синтетичної мінімальної зарплати; точне покриття фонду після округлення до копійки та залишок для студента з найбільшою сумою надходжень.
- Сума чистого управлінського доходу = надходження (UAH-еквівалент) мінус прямі податки та розподілений ЄСВ.
- Повтор оплати з однаковим `client_request_id` не створює повторного платежу; інші параметри із тим самим ID відхиляються.
- USD на PE рахунок: початковий `fx_pending`, знімок NBU-курсу і бази в UAH, округлення на рівні копійки, заборона зміни знімка повторною резолюцією.
- EUR на персональний рахунок: UAH-знімок для управлінського обліку, без PE-податку.
- Відсутність додаткових записів у фінансовому журналі під час FX-резолюції, збереження UAH/USD/EUR як окремих валют.
- Відсутність у браузерної ролі права безпосередньо фіналізувати курси податків та управлінського обліку.

## Запуск

1. Залишайтеся в гілці `feature/regression-stage-1-5-2`.
2. Скопіюйте файл із ZIP у `supabase/tests/database/`.
3. Переконайтеся, що запущений **локальний** Supabase.
4. Виконайте команду **лише з ключем `--local`**:

```powershell
npx supabase test db --local
```

Після 1.5.2f очікується **7 SQL-файлів і 264 тести** (212 попередніх + 52 нових), якщо всі попередні файли присутні. Це цільовий результат, а не підтвердження фактичного виконання 1.5.2g.

Не запускайте тести із `--linked` або Production connection string. **Не виконуйте `supabase db reset`**. До успішного PASS новий тест не комітити.

## Межі перевірок

Тест задає фіктивні значення NBU-курсу через службові фіналізатори. Він **не** перевіряє реальне отримання курсу з NBU, роботу зовнішньої Edge Function чи інтеграцію платіжних провайдерів. Реальні ставки мінімальної заробітної плати навмисно не зашиті в тест — для ізоляції використовується параметр викладача 800 000 копійок (лише всередині транзакції). Не замінює повноцінного тесту кількох податкових груп та міжмісячних платежів.

Якщо тест упаде, надішліть повний журнал помилок. Не змінюйте бойові таблиці або бізнес-правила для підгонки результату.
